# GaussDB 多主机 URL 三层修复（Agent Teams 并行执行）

## 根因（三层同源：多主机 authority 不被 WHATWG URL 接受）

1. 凭据注入层 `lib/store/connections.ts:107`：`mergeUrlCredentials` 用 `new URL(base)` 注入 userinfo，多主机端口段 `8000,10.192...` 非法 → 抛「连接 URL 无效，无法注入用户名/密码」（UI 报错）。
2. 驱动解析层：`gaussdb-connection-string` 同样 Invalid URL；带 `jdbc:` 前缀时 host/port 为空错连本机 localhost:5432。
3. 协议层：本机 PG 14+ 对 3.51 扩展协议回 `'v'`(0x76)，驱动不识别 → `received invalid response: 76`。

## 接口契约（先定死，teammate 并行的前提）

- `normalizeUrl(url) → { prefix, hosts, suffix }`：剥 `^jdbc:`；`prefix = scheme:// + userinfo@`；`hosts = [{host, port}]`（`h:p` 按最后冒号拆）；`suffix = path?query` 原样（容忍 `/gycwd?` 空参数）。任一台可重组 `prefix + host:port + suffix`；单主机/无前缀无损透传。
- `pickHost(driver, base, hosts, masterOnly) → host|undefined`：移植 GaussDB-MCP `probeHosts`——逐台 `new Client` 试连；`targetServerType=master` 时 `SELECT pg_is_in_recovery()` 跳备；全失败回退 undefined（外层回退首台报真实错误）。
- `mergeUrlCredentials`：`new URL` 失败时回退正则注入（`scheme://` 后拼 `encodeURIComponent(user):encodeURIComponent(pass)@`，与 redactUrl/驱动解码互逆），单主机路径行为零变化。

## Agent Teams 并行拆分（批准后执行）

**Teammate A（store 层，改 `lib/store/connections.ts`）**：mergeUrlCredentials 多主机回退注入；redactUrl 对多主机+userinfo 的脱敏验证用例；自带 vitest 单测（你给的两种 URL 逐字用例 + 凭据含特殊字符）。

**Teammate B（适配器层，改 `lib/adapters/sql-shared/pg-like.ts`）**：normalizeUrl + pickHost + 接线（gaussdb 多台时 probe 选台建池、跨库池复用、mainDb 用规范化 URL；postgresql 多主机透传不 probe）；`PgLikeDriver` 补 `Client` 声明；自带 vitest 单测（normalizeUrl 边界 + fake driver 的 pickHost：换台/跳备/全败回退）。

A、B 单条消息并行 spawn（general-purpose；若 Agent 工具不可用按记忆用 CreateWorkflow 指定 subagent_model）。

## 汇总（主代理收尾）

接口对齐检查 → `npm run test` 全套 + `npm run typecheck` → 汇报结果，你真机复测原 URL。

## 明确不做

不删 JDBC 参数、不补 `'v'` 解析、不做运行时 failover、不支持每台独立凭据/IPv6。
