DSH 插件 dsh-db-tool 加载错误记录
=====================================
记录时间：2026-09-28
当前状态：已从 desktop profile 卸载；卸载后该错误归零，其余 12 个第三方插件全部正常。

一、错误原文
-------------------------------------
dsh: error: [/197] createRequire.resolve.paths is not a function or its return value is not iterable

对应条目：/197   id=db-tool   name=dsh-db-tool   status=error

出现场景：DSH 0.1.7-rc.2 桌面版，desktop profile 的插件组合检查
（等价 `dsh --profile desktop --dump-config-schema` 的官方加载路径）。
同一检查中，其余 12 个第三方插件均无错误。

二、根因（DSH 0.1.7-rc.2 自带代码的 bug）
-------------------------------------
1) DSH 自带 @deepseek-ai/dsh-app-boot 的 lib/index.js 里有 6 处
   `createRequire(parent).resolve.paths(name)` 调用，其中 5 处未做空值防护。
2) Node 对「内置模块同名包」调用该 API 会返回 null
   （本机实测：resolve.paths('punycode') 返回 null；普通包返回数组）。
   对 null 做 for..of 即抛 TypeError —— 这就是上面的错误消息。
3) dsh-db-tool 的依赖链包含 npm 包 punycode：
   dsh-db-tool → mongodb → mongodb-connection-string-url → whatwg-url → tr46 → punycode
   因此该插件的加载路径必然触发这个 bug。

三、本机复现证据
-------------------------------------
运行环境：Electron Node（DeepSeek Harness.exe 加 --expose-internals），可直接访问 asar 内模块。

复现结果（最小用例）：
  createRequire('.../node_modules/dsh-db-tool/dist/index.js').resolve.paths('punycode')  =>  null
  createRequire('.../node_modules/tr46/index.js').resolve.paths('punycode')             =>  null
  createRequire('.../node_modules/dsh-db-tool/dist/index.js').resolve.paths('ssh2')      =>  array[11]

DSH 官方检查的诊断输出：
  卸载前：F:\DSH\_recon\dump-schema-err.txt      （含 /197 db-tool 错误）
  卸载后：F:\DSH\_recon\dump-schema-err-2.txt    （该错误消失，只剩 DSH 内置 agent-preset 的 4 条既有诊断）

四、插件作者已知该问题（包内自带 hotfix）
-------------------------------------
dsh-db-tool 包内提供：
  scripts/hotfix-core.mjs
  patches/dsh-app-boot-route-scoped-hotfix.patch
目标：@deepseek-ai/dsh-app-boot 0.1.7-rc.2 中未防护的那行 for..of。
修法：resolve.paths 返回 null 时回退到标准 node_modules 搜索链。

限制（本机为何没能直接用）：
  该脚本按「文件系统安装的 DSH」定位目标（找 DSH_HOME、PATH 上的 dsh、全局 npm 目录），
  而桌面版把 dsh-app-boot 打包在 F:\DSH\resources\app.asar 内，脚本找不到文件，无法应用。

五、可选修复路径（供向 DSH/插件作者反馈）
-------------------------------------
1) 等 DSH 上游修复（推荐）：该 bug 属于 0.1.7-rc.2 自带代码，任意「依赖树含 core-module 同名包」的插件都会触发。
2) 重打包 app.asar 应用该 hotfix：需先关闭 DSH 应用，修改应用安装文件，版本更新时会被覆盖，有风险。
3) 插件侧规避：依赖树中避免引入 core-module 同名包（例如替换 punycode 的实现）。
