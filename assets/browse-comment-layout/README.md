# 数据浏览对象树表行注释布局：改动前后对照取证

- 场景：数据浏览页签 → 展开树壳 → 展开示例库（postgresql）→ dbt_shot 库 → public schema → 表清单（未选表）
- viewport 500×774，@2x 采集（成图 1000×1548），亮/暗各一组；浏览器 colorScheme 由 Playwright 上下文显式设为同侧，画布底色用宿主主题 token 解析值（亮 `#ffffff` / 暗 `#151517`）
- Before = `52c4b9c`（1.9.12，PR #24 的拼接形态：表名与注释以「 · 」连在同一标签里），After = Apple 设置列表式左右分区（表名居左、注释右对齐置灰、无竖向隔断线）；两版均为各自提交干净构建 `dist/` + 各自真实 `client.js` + 真实插件 HTTP API（授权/审计链路全真实），React 走真实渲染路径
- 数据源：本机专用 PostgreSQL 17 集群（127.0.0.1:5433，仅 dbt_shot/postgres 两库），orders/products/users 三表 + v_order_stats 视图，`COMMENT ON TABLE` 中文注释；连接/授权经真实插件 API 建立（ro 授权）
- DOM 机器校验（tree-rows.json）：before 表行为「orders · 订单主表」拼接单串、视图为「v_order_stats · VIEW · 订单状态统计视图」；after 名称列为纯表名/名称+类型，注释为右列独立块（orders 行名称=`orders`、注释块=订单主表，视图行名称=`v_order_stats · VIEW`、注释块=订单状态统计视图），全树无 `.dbt-treesep` 元素
- 几何机器校验：orders 行注释块右缘 472 = 行右缘 484 − 12px 行内边距（右对齐）；表名文本右缘 x≈133，注释块左缘 x≈428，中间为分区留白（间距 295px）；注释 11px/400、`--dbt-text-secondary` 解析值（暗 rgba(235,235,245,.6) / 亮 rgba(60,60,67,.6)）；注释块限宽 45% 行宽保证长注释不挤占表名
- 像素机器校验：四图与底色亮度差 > 60 的文字像素占比 0.98%–2.24%（> 0 判有效）；orders 行带内全列扫描最长竖向连续非底色段仅 21–23px（文字墨迹量级），确认无竖向隔断线残留（此前隔断版本为 42–64px）
- 布局迭代记录：首版 `41695e3` 注释右对齐 + 竖向隔断贴注释（各行隔断随注释长度参差悬空，反馈「太丑」）；二版 `15a2705` 注释紧跟表名紧凑相邻（反馈「贴合太近」）；终版 `eb09330` 按 Apple 设置列表样式改为左右分区留白、去掉竖线
